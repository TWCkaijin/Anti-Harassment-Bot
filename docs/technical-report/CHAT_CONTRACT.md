# Chat v4：自然回答、文字摘要與 PII 對照

更新日期：2026-10-09。描述本地 v4 實作，保留 v1-v3 相容路徑；不代表正式環境已部署此版本。

## 回答與串流

複雜、法律、期限或程序問題先由模型整理可核對的需求、陳述、範圍與檢索需求，再查詢資料庫，最後把原始條文與理解結果一起交給模型回答。簡單支持可直接完成。法律或程序需求若缺少會影響方向的關鍵事實，可先追問而不檢索。校園個案須分別釐清當事人與對方的角色；兩方皆未知時先問當事人、再問對方，一輪一題。已知／已拒答不重問，未知或拒答時提供附條件的一般資訊，立即安全協助優先。這是模型語意判斷的提示與路由契約，不以學校關鍵字硬編碼法源。理解結果不是法源，第三人稱、假設與引述不等同使用者親身經歷。管理員的語氣與溝通原則仍會傳入；輸出格式由 v4 契約控制。

v4 沒有固定的「方向／依據／下一步」標題，也不要求 `answer_sections`。模型以 `answer_units` 內部結構產生自然段落與 `source_ids`。增量解析器取得完整單元後才檢查來源 ID、法名條號與期限／版本條件，再送出 SSE `delta`；完整答案與末尾 metadata 尚未完成時，第一個合法段落已可顯示。未完成物件、原始 JSON 與未知來源 ID 不會成為答案。

無依據的法律主張按局部處理，修正模式全回覆只插入一次共同限制，保留其他可支持內容。標記模式保留待核對文字。引用對應檢查不等於語義上每個法律推論都已證明，仍需個案及專業覆核。

`analysis` 是已完成的情境整理與檢索摘要。獨立 `reasoning` 事件只接收供應商公開的 `text` 或 `summary`；不解碼加密資料，也不展示簽章或工具參數。`enable_analysis` 控制分析摘要；推理文字另外要求開發設定 `enable_reasoning_display=true`（預設 false）。關閉顯示時仍保留模型的 reasoning effort，但要求供應商 exclude reasoning，且後端 JSON／SSE 和前端顯示均另行阻擋推理文字；模型不提供 reasoning 時，正式答案照常處理。推理說明以淺色斜體並標示非已驗證答案，生成中展開、完成後可收合。它只存在頁面記憶體，重新整理、匯出與後續請求都不保留；可核對的 analysis 與正式答案照常儲存。

已發送 analysis、reasoning 或答案段落後，伺服器與前端均不自動完整重播。取消、斷線或結尾格式錯誤保留已顯示段落並標示未完成；摘要、追問及資源按鈕只在完整 `done` 驗證成功後提交。

本機格式或單元驗證失敗時，立即停止送出新的答案／reasoning，但不直接把上游生成中斷成 cancelled：最多再接收 10 秒，並沿用 256,000 字元回應上限，等待串流結尾後回報原始驗證錯誤；丟棄的後續內容不累積或發布。超時／超量仍會關閉連線。使用者停止、斷線或 task cancellation 一律立即傳遞，沒有背景重播。伺服器日誌只新增白名單 contract_reason／contract_stage，不記錄原文或模型回應。

模型呼叫階段與傳輸 chunk 不同：一般聊天的直接支持路徑只呼叫一次；需整合的路徑先完成 plan，再按設定檢索，最後另一次模型呼叫產生答案。每次模型呼叫各自使用供應商串流；answer_units 是同一次回覆內的段落，不是每段另呼叫一次模型。單元最多 32 個、每個 text 最多 2,000 字元，組合後公開答案最多 6,000 字元。可選 reranker 的呼叫另計。

## Schema 與模型端約束

`guided_v4.py` 由 Pydantic 定義理解、回答與三法預測四種 schema。請求使用 `response_format.type=json_schema` 及 `json_schema.strict=true`；object 禁止額外欄位、列明必需欄位，選項以 enum/Literal 限制。最終回答的 `source_ids` 動態限制為當次檢索 ID，沒有來源時只容許空陣列。

第一階段模型回傳為 `{"plan": ...}`，`plan` 使用三個互斥的巢狀 schema 分支：`SynthesisPlan` 固定 `requires_synthesis=true` 且 `answer_units` 必須為空；`DirectPlan` 固定 `requires_synthesis=false`、`retrieval=null`、至少一段答案，intent 限於 support／other；`ClarificationPlan` 保留法律／程序／期限 intent，但 sufficient=false、immediate_safety=false、requires_synthesis=false、retrieval=null，且必須有 question。釐清分支等完整契約與追問開關驗證後才發布答案，關閉 auto_clarify 時也從供應商 schema 移除此分支。相同分支型別也用於本機驗證，避免只在 Python validator 才禁止矛盾組合。第二階段維持原格式，前端 API／SSE 格式不變。解析器在 plan 內持續逐段送出直接回答，不等待整個包裝完成；結尾仍須完整驗證。巢狀 union 保持 object 根節點，符合 [Structured Outputs 的根節點限制](https://developers.openai.com/api/docs/guides/structured-outputs)。

第一階段的 `UncitedAnswerUnit.source_ids` 以 `maxItems=0` 限定為空，因為此時沒有檢索文件。相容修正僅限直接回答中恰好為 `["user"]` 的非文件標記：清除該標記後重新驗證，診斷記錄 `non_document_user_reference`，不更動原始串流、不產生虛構來源。其他未知 ID、混合 ID 與所有第二階段引用仍採原有檢查；條號／期限內容檢查不受影響。

共用路由函式加入 `provider.require_parameters=true`，避免 OpenRouter 選擇不支援請求參數的端點；保留 provider 排序與 reasoning 設定。不接受 schema 的端點回報失敗，不切換為自由文字或無 schema 重試。串流與非串流、兩個階段皆套用。

本機仍拒絕錯誤型別、不完整終止、非預期 choice、拒絕／工具呼叫、重複 JSON key、NaN／Infinity 與多餘文字；不把字串 `"true"` 強制轉成布林值。Pydantic 跨欄位規則與引用／摘要證據檢查繼續保留，因為格式有效不代表內容正確。

[OpenRouter 官方說明](https://openrouter.ai/docs/guides/features/structured-outputs) 指出 strict schema 的原生強制能力依供應商而異。這裡強制送入 schema 並篩選支援端點；未用真實模型驗證個別端點的解碼器，不能宣稱所有供應商均有相同的逐 token 約束保證。

`rag_used.sources` 仍只代表回答引用的來源；新增 `rag_used.retrieval` 由實際檢索程序產生 status、data_types、sources。介面獨立顯示已檢索法律知識庫／裁判資料庫／救濟管道及可展開結果；查無資料與檢索失敗分開標示，停用或未查詢時不顯示已檢索。

## 單一文字摘要

案件 schema 3 以 `summary`、`summary_origin` 與 `revision` 代替固定欄位。本機 storage schema 4。舊 schema 的已有值、未知、拒答與多值轉為可讀文字，另保留 `legacyCaseFacts`；不重讀舊聊天猜測案件資訊。驗證失敗、未知未來版本禁止覆寫原紀錄。合法舊摘要若超過 4,000 字，提供完整文字供人工縮短；全部過長摘要整理完、原始儲存仍未被其他分頁修改時，才一次原子寫入並解除唯讀，完整舊 facts 仍留在備份。

摘要按鈕位於最新有效 AI 頭像下，開啟的是同一份目前摘要。若儲存更正使原回答全部失效，精簡工具列保留摘要入口。查看不停止回答；開始編輯停止該回覆並擷取當時版本，可取消、儲存或儲存並重新回答。

模型摘要採逐字可核對內容，區分情境範圍；使用者可自由改寫，保存後以使用者版本為準。晚到回覆必須同時匹配對話、請求擁有者及版本才能更新。編輯界線之前的歷史不再送入後續模型請求。重新回答沿用原始需求，但以更正後摘要為唯一案件事實，不把原需求中的舊資訊當作新陳述。後續真正的新訊息仍可補充摘要。非空文字摘要不能靜默降級到 v1–v3。

v4 追問沒有固定 `fact_key`，使用問題 ID、HMAC token、摘要版本、範圍、選項與選取上限驗證。單／複選、自行補充與未知／拒答互斥規則保留。摘要更新與同回覆的追問使用一致的更新後版本。

## PII 對照與版面

PII 仍預設啟用。有效日期區間與小節編號不再誤當信用卡號或 IP；中文緊鄰電話、信箱及身分證的邊界也納入遮罩。角色、行為、一般日期與法條資訊仍可使用。不能僅憑兩次模型回答不同就推斷是遮罩造成，需比較實際輸入、檢索查詢、來源及後處理。

管理員「本次診斷測試」保留最近兩次結果，並排顯示有效設定、訊息／歷史／摘要的處理前後、PII 種類、檢索與改寫。按「只切換 PII 再測一次」會沿用原始輸入及完整可覆寫設定，只翻轉 PII 總開關；環境設定不會儲存。後端維護訊息為 `null` 時會正規化為空字串，仍可執行對照。輸入處理前後僅在驗證後的本次測試回應中顯示，不新增一般聊天原文後端保存。

品牌橫幅只在尚無訊息的首頁顯示。進入對話或送出首則訊息後，橫幅與側欄收起；仍保留小型選單、連線及重連入口。桌面 hover 箭頭以覆蓋方式預覽，離開約 200ms 收起；點擊可固定開啟，串流更新不重設固定狀態。焦點、重新命名與更多選單可阻止自動收回。窄螢幕／觸控以點擊抽屜操作；追問選單在自身區域捲動。
