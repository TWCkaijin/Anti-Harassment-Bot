# 瀏覽器隱私處理

更新日期：2026-11-10。本頁描述目前工作目錄中的程式；雲端版本是否已更新須另行核對。2026-10-09 產製的使用者手冊與 PDF 是舊版閱讀快照，當時的自動送出說明不適用於此版。

## Client 送出流程

原文輸入 → 瀏覽器本機規則遮罩 → 顯示完整待送出內容供人工檢查及修改 → 使用者確認 → 固定請求快照 → 後端 → 可選的後端第二層遮罩 → 模型／檢索。

每次新聊天請求都先準備並檢查當次訊息、選入的兩種角色歷史、摘要、舊版 facts 與追問資料。取消確認或準備失敗時不呼叫聊天 API；同一請求的自動重試使用已確認的快照，不重新讀取原文。切換對話、修改摘要與連線版本變更時，請求擁有者檢查仍會取消過期請求。

目前使用的是瀏覽器規則遮罩。常見電話、email、台灣身分證件格式、卡號或長編號、IP、網址及明示姓名／地址欄位會遮罩；一般日期、法條、角色與 110／113／119 會保留。規則可能漏掉自由文字中的人名、單位、住址、罕見事件或跨段線索，因此確認視窗需要使用者實際檢查與修改，不能視為匿名保證。瀏覽器小模型仍停留在獨立驗證用途；在固定 120 案及獨立人工標註 holdout 通過前，不加入正式送出路徑。

`privateRequest.ts` 建立並登記不可變的本機處理後請求物件；官方前端傳送層拒絕未登記、複製或篡改的物件。這是官方前端的流程約束，不能證明任意直接 HTTP 客戶端已遮罩。後端 PII 開關另行控制。追問 token 是簽章而非加密；不明格式或敏感的追問 metadata 會被移除，改以遮罩後的一般文字送出。

Admin 單筆診斷和批次工具沿用本機規則遮罩，但走自己的測試與整批預覽流程，不逐筆開啟 Client 確認視窗。診斷中的「輸入處理前」是指後端收到的本機處理後文字。

## 圖片、App Check 與本機紀錄

圖片目前在 Client 與 Admin 診斷端點均停用；即使既有 Firestore 設定記錄 `enable_image_upload=true`，後端仍回 `422 image_upload_disabled`。圖片沒有 OCR、EXIF 或臉部去識別流程，因此這個設定值不能當成上傳許可。

啟用 App Check 的 Client 會在聊天請求前透過 reCAPTCHA Enterprise 取得 token，並由後端驗證。取得 token 的程序不需要聊天文字；若啟用模式無法取得 token，前端不送出聊天請求。App Check 是來源驗證，不代替文字遮罩或人工檢查。

新訊息與該次送出摘要保存本機處理後文字；既有紀錄、備份及手動儲存摘要不會批次清除，選入後續請求時會重新遮罩。共用裝置上的本機紀錄與匯出檔仍可能包含個資。人工維護的 prompt、法源、直接 API 客戶端及平台 IP／連線資訊不在這項瀏覽器處理範圍內。
