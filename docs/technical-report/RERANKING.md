# Provider 排序、重排與批次評分

## 使用方式

管理介面「系統設定 → Provider 與 Reranking」可選 provider 排序、啟用重排、選取／輸入模型並調整候選數、等待上限及重排文字長度。模型清單由管理員 API 取得並快取 10 分鐘；清單暫時失效仍可手填。

本機 `.env` 新增 `OPENROUTER_PROVIDER_SORT=latency`、`RAG_RERANK_ENABLED=true`。程式及 `.env.example` 預設為 `auto`、`false`，所以既有線上環境不會自行啟用；本次未修改 Firestore 或部署。若 Firestore 已有同名欄位，仍依既有優先序覆蓋本機值。變更環境變數後須重啟本機後端。

| 設定 | 預設／範圍 |
|---|---|
| `OPENROUTER_PROVIDER_SORT` | `auto`、`latency`、`throughput`、`price` |
| `RAG_RERANK_ENABLED` | false |
| `RAG_RERANK_MODEL` | `cohere/rerank-4-fast` |
| `RAG_RERANK_CANDIDATE_K` | 20；1–50，且不得小於最終 Top K |
| `RAG_RERANK_TIMEOUT_SECONDS` | 1 秒；0.1–10 秒 |
| `RAG_RERANK_MAX_CHARS_PER_DOC` | 2,000 字元；100–20,000 |

Runtime 欄位為上述名稱的小寫版本。單次管理測試覆寫優先於 Firestore，其次環境變數與程式預設。供應商排序合併到既有 reasoning 參數；auto 不傳 `provider.sort`。排序適用聊天／預測各模型階段與 rerank。

## 重排邊界

共用檢索層先使用一次 embedding 並行檢索，再合併去重與篩選；全部候選只進行一次 OpenRouter `/rerank`。RAG 關閉或候選數不超過最終保留數時，不呼叫重排。`rag_retrieval_top_k` 仍控制最終上下文；混合來源沿用每種類型至少一筆的規則。

精確法條命中及來源類型保留優先權。送往重排的文字有長度上限，實際回答仍用原始文件內容及來源 ID。回傳索引、完整性與分數須通過驗證；不以未校準分數門檻刪除法源。

整個 HTTP 交換受 deadline 限制；逾時／錯誤使用原始候選排序，不重試、不改模型、不重新檢索。上層取消會繼續傳播，不轉成成功。每次請求建立 HTTP client，避免 Firebase WSGI 不同 event loop 共用連線。

`retrieval_ms` 保留包含 embedding 的原意，但不包含新增的 `rerank_ms`。`candidate_retrieval_ms` 是候選檢索觀測值，和 retrieval_ms 重疊，不應相加。管理診斷另記錄重排狀態、實際模型、候選／保留數與錯誤類型，不含文件／查詢內容。

## 批次預測與統計

在「批次預測」選擇檔案、工作表、情境欄位及參考答案欄位。預設建議「適用法規」欄，可選擇不評分。準備後欄位與参考資料固定；答案留在瀏覽器本機，不送給模型。

新輸出標籤：性工法＝性別平等工作法、性平法＝性別平等教育法、性騷法＝性騷擾防治法。參考答案另接受正式法名與舊稱「性教法」；逗號、頓號、分號、斜線、換行可分隔多個法規。混入無法識別的標記則整格列為無效，不猜測敘述內容。

**任一法規命中就算正確**，忽略順序及多餘預測，因此這是包含命中率，不是完整集合一致率。

- N：全部非空情境；R：有有效參考答案的情境。
- A：成功回傳法規答案；AR：其中有有效參考答案者。
- C：命中任一參考法規；F：目前最終失敗；U：資訊不足＋不適用三法。
- 總正確率 C/R；回答正確率 C/AR；失敗率 F/N；無法評估率 U/N；回答率 A/N。
- 無參考答案的列排除於兩種正確率；仍納入回答、失敗及無法評估率。零分母顯示「—」。
- 暫停或進行中的統計標示暫時計算及未完成數；失敗重試以最新結果重算，不累加嘗試數。

下載 Excel 保留原始工作表內容，新增預測、狀態、秒數、比對結果、命中法規與無法預測原因欄；另加名稱不衝突的「預測統計」工作表，記錄百分比、分子、分母、欄位選擇、模型、設定與契約指紋。設定長文字按 Excel 儲存格限制分段保存。字串以文字儲存，避免被解讀為公式。

新的 schema／提示已更新契約指紋，舊批次須重新準備。歷史 Excel 及原始評測結果沒有回寫或改名。

## 設定與無法預測原因
系統設定依序為「模型設定」「處理流程」「檢索設定」「維護模式」。聊天模型、生成參數、Provider 與 Rerank 模型設定集中在模型區。Reranking 啟用控制移至流程區，僅出現一次。後端 PII 使用主要開關，細部遮罩範圍收合於進階設定；關閉主要開關時範圍控制停用，但保留先前各階段的設定。瀏覽器固定在本機文字遮罩完成後自動送出，不再提供人工確認開關。

導覽先列系統、Prompt、Skills 設定，再以分隔線及「驗證及測試」標題收納本次診斷測試與批次預測；切換頁籤仍保留批次進度。

適用法規預測新增必填 `decision_reason`：可預測時為 `null`；資訊不足或不適用三法時，必須提供最多 300 字的具體原因。後端、前端與 CLI 都驗證此限制。原因顯示於單筆診斷與批次結果，瀏覽器下載以純文字另存欄位；操作失敗仍顯示經整理的錯誤訊息。契約指紋隨 schema／prompt 變更，舊批次不得無提示地沿用；既有歷史檔案不重寫。前後端須一起更新。
