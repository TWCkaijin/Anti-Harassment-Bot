# 已知限制與後續維運事項

版本日期：2026-10-08。下列事項來自目前原始碼、設定及舊待辦的重新整理。本次整理不進行應用功能重構，也不將歷史測試或候選資料視為正式服務品質驗收。

## 部署與權限

- 現有 CI 部署流程仍使用長效 Firebase token／service-account JSON，且在工作目錄寫入部署設定。本次收緊 source 排除規則，但尚未改為短效部署身分或雲端 Secret Manager；後續部署須核對 runtime 注入與權限。
- 管理 API 仍使用共用靜態 key，前端會保存至 localStorage；尚非具名登入、MFA、短效 session 或可信任操作身分稽核。
- preview 與 production 仍使用既有專案及共用 scenario_scripts；runtime document 分離不等於資料、身分與費用完整隔離。
- App Check 與 rate limit 有設定入口，但正式開啟狀態未查核；行程內限流不是跨 instance 的全域配額控制。
- 本次不變更現有推送觸發部署方式。既有 remote 與 Git 歷史原樣保留；內部檔案即使移出目前目錄，也可能在歷史中查得。

## 隱私與資料保存

- 前端文字遮罩可能漏掉姓名、特殊事件或組合識別資訊；人工確認可由管理設定關閉。不能宣稱完全匿名。
- 圖片支援原圖傳送；格式及大小驗證不等於 OCR、EXIF、臉部或內容去識別。圖片與歷史本機紀錄仍可能含敏感資訊。
- localStorage 與下載檔不提供伺服器端的集中清除或保存期限保證。reasoning 僅暫存於頁面，不代表其他摘要與診斷一律不保存。
- 雲端日誌、上游供應商資料保留政策及帳戶設定需另行確認；本機測試不能證明實際平台保存行為。

## RAG 與評估

- resource/ 全部原樣保留，其中既有結果有各自的模型、提示、時間與驗證範圍；不作為本次交付的新驗收結論。
- 法源快照有來源及版本記錄，但未於本次更新或比對雲端。data/documents 仍保留舊 seed，其既有稽核指出 metadata 缺漏及部分舊內容；不可直接將舊 seed 當成最新法源匯入。
- 資料保留不等於所有判決與來源已完成授權、去識別或正確性審核；來源及再利用條件須由維運者逐項確認。
- 引用 ID、條號或法名檢查不能證明完整語義支持。三法批次採任一法規命中率，不是完整法規集合一致率，也不是法律準確率。
- 行為測試的規則提示與人工結論分開，待覆核不能算通過；候選 Excel 不能直接當專家 gold。
- 模型品質、真實 RAG 召回、平台 SSE、併發效能、P95、帳單與法律專家覆核未在本次驗證。

## 維護事項

- Runtime config 的完整修訂歷史、併行編輯保護及雲端回復流程仍需補強；先保存修改前設定。
- 健康檢查回應不代表 Firestore、模型與索引均就緒；需另做 readiness 與外部依賴檢查。
- 前端 API 無環境設定時仍有舊 port 8000 fallback；交付範本與啟動指令已明確指定 Flask 的 5000。
- 既有 preview workflow 指定 30 天，留言文案仍可能寫 7 天；以部署結果為準。
- 依賴仍混有開發／執行工具，工具鏈版本固定策略及套件弱點檢查需後续維護；本次未升級套件。
- 大型前端 chunk、模組拆分、可及性、圖片生命週期、同步 Flask 與非同步 client 的高併發行為，均不因目錄整理而視為已改善。實際建置警告與測試結果見交付驗收。
