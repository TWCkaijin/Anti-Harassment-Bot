120 則都回傳空集合。15 則本來沒有敏感片段的案例符合預期，其餘 105 則失敗。有效 JSON 不等於辨識正確；若直接接入聊天，這些漏判文字就可能未被遮罩。因此本次沒有接上送出流程。

模型首次載入 **107.01 秒**，13 次下載共 **352,462,397 bytes（336.13 MiB）**；同設定檔重新建立 Worker 後，快取載入 **0.857 秒**，下載 0 bytes。內容量不含 HTTP/TLS 開銷。此輪延遲主要反映空集合輸出，不能推估成功抽取多個片段時的速度。

第一次開發試跑觀察到模型把整句列為敏感片段；在完成 75 則開發案例、尚未執行保留驗證集時停止。加入四則與評估資料分離的固定示例後，鎖定 v2 設定完成全部 120 則；之後沒有用保留驗證結果調整提示再評分。

四個獨立控制案例確認模型能進行基本推論，但不能推定已具備本案需要的抽取能力：

- 算術控制可回覆 `1+1=2`。
- 簡短姓名抽取提示可找到「李四」，但漏掉同句的「王五」；有無 JSON schema 均如此。
- 完整 v2 提示即使移除 JSON schema，仍回傳空集合。

以上支持「此模型／提示組合不合格」，不代表所有瀏覽器模型或所有提示都不適用。控制案例沒有改變驗收結論，原始輸出另存 [control-probes.json](results-2026-10-09/control-probes.json)。

## 安全與程式檢查

- 瀏覽器只下載靜態頁面與公開模型資源；沒有聊天、OpenRouter 或 Firestore 請求，沒有不允許的網路請求或頁面錯誤。
- Worker 使用 IndexedDB 快取；所有模型下載經固定 URL 白名單，拒絕帶有查詢參數或內容的請求。模型輸入僅走本機 Worker 訊息通道。
- 在實際 Chrome 中透過測試注入，讓 Worker 的 WebGPU API 不可用：顯示初始化失敗、測試按鈕維持停用，沒有嘗試外部或聊天 API 請求。這是可重現的失敗模擬，不是另一台實體不支援裝置的驗證。見 [失敗流程結果](results-2026-10-09/failure-smoke.json) 與 [實際畫面](results-2026-10-09/unsupported-webgpu.png)。
- TypeScript、完整前端 ESLint、production build 通過；Vitest **44 個測試檔、622 個測試通過**，其中新增 10 個測試涵蓋抽取驗證、分段、替換、逾時、取消及無網路 fallback。
- 本次未修改後端程式，沒有重新宣稱後端測試、正式部署或正式模型服務已驗證。
- 保護範圍共核對 31,818 個既有檔案，沒有新增項目；`resource/`、虛擬環境與真實憑證均一致。兩個 Git 中繼資料檔 `.git/FETCH_HEAD`、`.git/gk/config` 在執行期間變動；本次沒有執行 Git 寫入指令，變動來源尚未確認，也沒有回寫還原，以免覆蓋其他工具的操作。見 [核對紀錄](results-2026-10-09/protected-files.json)。
