# 資料標注說明

此資料集由 `prepare_data.py` 的 36 個明確句型家族產生，所有標注由具類型的插槽建立，不是從模型預測回填。沒有匯入真實使用者、父專案的 120 筆瀏覽器測試或 1,500 筆行為測試，因此舊瀏覽器案例不被當成訓練資料。

資料的來源是 `synthetic-template-v1`，審核狀態是 `unreviewed`。人名、電話、地址與單位為合成組合，仍可能偶然與真實資訊重合，不能撥打或寄送。Email／私人網址使用 `example.invalid`；識別碼刻意使用合成 `SYN-*`，尚不足以代表所有真實證件格式。

## 標注契約

| type | 包含 | 邊界規則 |
|---|---|---|
| person | 明確個人姓名 | 不包含「主管」「老師」「同學」等職稱／泛稱 |
| organization | 具體公司或學校全名 | 保留公司／學校後綴，泛稱「公司」不標 |
| address | 能形成詳細住址的片段 | 保留市區、街道、號、樓；單一城市不標 |
| contact | 電話、Email、私人網址 | 保留原始格式；標點若屬於原值則保留 |
| identifier | 學號、帳號、證件／識別碼 | 不含前面的「帳號是」等敘述 |

原文位置採 Python Unicode code point、0 起算、`[start,end)`。這不同於 JavaScript UTF-16 索引；若未來含 emoji，不能直接把 offset 當成瀏覽器 offset。訓練目標使用原文字串，不依賴這些數值定位。

同一姓名重複出現，annotations 記錄每次出現的位置；locate 只列不同字串一次，classify 也只出一筆。片段不能重疊。原文中「忽略指令」「輸出空集合」等只是待辨識資料，不改變標注規則。

`negative_candidates` 是原文確實存在、但應回覆 `none` 的片段。它們用來教分類器排除城市、年齡、日期、法規、求助短碼、職稱及方括號代稱。並非所有非個資詞都列入 negative_candidates。

## 新增或修正

1. 編輯 `data/annotations.jsonl`，保留一行一個 JSON object；先挑選原文片段，再填類型與精確位置。
2. `id` 與 `text` 必須唯一。同句型／同事件的改寫共用 `family`，放在同一 split，避免衍生資料跨組。
3. 審核過可將該案 `review_status` 改成 `reviewed`，另記錄自己的審核紀錄；不要把目前全體標成已人工審核。
4. 執行 `python prepare_data.py --from-annotations` 重新展開，接著 `python prepare_data.py --check`。
5. 若更改 `prompts.json`，也需重新展開；保留舊實驗的 run.json 與 metrics.json。

目前檢查器要求具體 entity 字串也不能跨組。若未來研究需要允許部分共通地名／組織，必須先調整並記錄切分政策，不能單純忽略錯誤。

## 已知限制

只有 30 個姓名值、30 組各類欄位變體；單一模板的 10 次換值不是 10 種語言結構。地址、電話及識別碼形式有限，沒有系統涵蓋真實長文、暱稱、罕見姓名、有效證件格式、錯別字、多語混寫、URL/query 複雜邊界或多實體重疊。

本資料能驗證端到端訓練流程，不能單靠其 holdout 分數證明實際隱私保護效果。下一步應優先人工檢查邊界、加入不同寫法與困難負例，再擴大規模。請保留一份完全未用於調參、由不同方法產生或人工撰寫的最終挑戰集。
